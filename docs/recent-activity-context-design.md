# 跨会话近期感知设计

> 状态：已按本文实现，并随 `0.8.0` 于 2026-07-31 发布。
>
> 目标插件：`astrbot_plugin_conversation_flow`（凝心溯溪-言）
>
> 协作插件：`astrbot_plugin_relationship`（凝心溯溪-情）提供人工验证的匿名自然人等价身份；`astrbot_plugin_identity_guardian`（凝心溯溪-序）逐轮裁定跨作用域读取。
>
> 本文描述 `0.8.0` 的实现；功能默认关闭。

## 1. 结论

在“言”中新增一个轻量、只驻留内存的“跨会话近期感知”模块，负责让 Bot 弱感知同一自然人在其他已绑定账号或会话中刚刚说过什么。

它不复制 Memory Companion 的长期记忆，也不把其他窗口最近 N 条消息直接交给模型。核心策略是：

1. 保留较宽的近期事件池；
2. 先做身份、作用域、隐私与当前会话优先级硬过滤；
3. 再按明确承接、实体/话题重合和时间衰减选择候选；
4. 将同一来源的连续消息整理成最多两个“证据胶囊”；
5. 只把确实相关的胶囊作为弱背景注入，当前消息和当前会话永远优先。

时间只参与排序，不能单独让一段内容获得注入资格。

## 2. 问题定义

当前 Memory Companion 的近期跨窗口层默认读取近 30 分钟、最多 6 条消息，主要依据同平台、同 Bot、同原始 UID 和时间倒序筛选。语义相关性、当前会话焦点和话题状态主要交给主模型通过提示词自行判断。

这会产生两类问题：

- 用户只说“好”“嗯”时，其他窗口中时间较近的话题可能压过当前窗口正在处理的事情；
- “用户刚才聊过游戏”可能被模型扩大解释成“用户刚才正在玩游戏”。

第二种不是记忆过期，而是证据含义被扩大。新模块必须保留“聊过游戏”这个经历，同时禁止把“谈论某事”推断为“当前正在做某事”。

## 3. 目标与非目标

### 3.1 目标

- 同一自然人在两个已绑定私聊账号间切换时，可以自然承接刚才的话题；
- 私聊可在确实相关时弱感知该自然人刚在群里说过的话；
- 群聊只有在当前消息明确同意时才可承接私聊，并区分“只续话题”和“公开必要细节”；
- 当前窗口的明确陈述、最近轮次和正在处理的请求始终优先；
- 普通请求不新增同步 LLM 调用，不同步联网；
- 不读取或注入第三方群成员消息；
- 与 Memory Companion 的长期记忆、近期事实保护和阶段总结分工清楚；
- 未安装、未绑定、契约失配或身份变更时失败关闭。

### 3.2 非目标

- 不重做长期记忆、画像、知识图谱或阶段总结；
- 不把不同自然人的账号按昵称、显示名或聊天内容自动合并；
- 不让自然人绑定继承主人、友好、保护、黑名单或群管理权限；
- 不在缺少当前轮明确同意时向群聊暴露私聊内容；
- 不保存系统提示词、工具参数、工具返回 JSON、账号标识或第三方群消息；
- 不使用额外的前置分类模型判断是否承接。

## 4. 职责边界

| 模块 | 本设计中的职责 | 明确不负责 |
|---|---|---|
| 言 | 近期事件缓存、当前会话仲裁、相关性选择、胶囊生成、弱注入 | 自然人绑定、长期记忆、权限继承 |
| 情 | 提供管理员人工验证的自然人等价身份 | 选择话题、保存近期正文、决定是否注入 |
| 序 | 通过 `identity.context_bridge_authorization@1.0` 逐轮裁定读取方向与私聊进群同意模式 | 不读取近期正文、不保存同意、不执行发送 |
| Memory Companion | 长期记忆、近期事实保护、阶段总结与语义召回 | 启用本功能后不再负责近期跨窗口原文注入 |

当前实现只允许以下方向：

| 来源 | 当前窗口 | 结果 |
|---|---|---|
| 已绑定私聊 | 已绑定的另一私聊 | 允许弱关联 |
| 同一自然人的群聊发言 | 该自然人的私聊 | 允许，但不能仅凭时间命中 |
| 已绑定私聊 | 当前群聊 | 默认拒绝；当前群消息明确同意时只对本轮放行 `topic_only` 或 `details` |
| 群聊 | 另一群聊 | 拒绝 |
| 第三方群成员消息 | 任意窗口 | 拒绝 |

任何方向都必须同时通过情的匿名同一人校验和序的版本化授权。序缺失、停用、契约失配、目标作用域不符或同意表达不明确时失败关闭。

## 5. 身份与授权契约

### 5.1 匿名连续身份

“言”不得读取“情”的身份数据文件或直接调用 `IdentityRegistry`。新增只读契约：

```text
relationship.continuity_identity@1.0
```

建议入口：

```python
contract = relationship.continuity_identity_contract()
identity = await relationship.resolve_continuity_identity(event, req)
```

最小返回结构：

```json
{
  "version": "1.0",
  "verified": true,
  "reason": "admin_verified_binding",
  "continuity_key": "opaque-process-local-key",
  "relationship_profile_id": "default",
  "binding_mode": "admin_verified",
  "permission_identity_mode": "raw_platform_account",
  "grants_permission": false
}
```

约束：

- `continuity_key` 是进程内不透明键，不返回自然人 ID、UID、平台、Bot ID、UMO、显示名或账号列表；
- 键由进程随机密钥对自然人、关系人格和当前账号成员集合做 HMAC；解绑、合并、换绑或插件重载后键变化，旧事件自动失去可达性；
- `grants_permission` 固定为 `false`，契约只证明账号属于同一自然人，不授予任何平台权限；
- 身份事务进行中、未人工绑定、关系人格不一致、账号信息不完整或解析歧义时返回 `verified=false`；
- `continuity_key` 只存在于“言”的内存缓存，不写统一请求上下文、日志、Page 或持久化文件。

提供方与消费方必须校验契约名和 major 版本。实现时需同步更新 `plugin/CONVENTIONS.md` 的契约表和双方回归测试。

### 5.2 逐轮读取授权

“言”不得自行解析同意关键词后绕过序。新增只读契约：

```text
identity.context_bridge_authorization@1.0
```

入口为 `authorize_context_bridge(event, source_scope, target_scope)`，固定返回 `version`、`authorized`、`reason`、`mode`、`explicit`、`max_chars` 六个字段。私聊到私聊与本人群聊到私聊可只读放行；群聊到群聊始终拒绝。

私聊到群聊只读取当前事件自己的 Plain/Text 段：

- “继续私聊的话题”返回 `topic_only`，言只能说明近期存在相关对话，并使用当前群消息已经公开写出的主题，不能渲染私聊正文；
- “把私聊具体内容发到群里”返回 `details`，言最多渲染 600 字必要短片段，并额外遮盖密码、Token、Cookie 等凭据；
- 否定、撤回、假设、举例、规则讨论、疑问式试探、引用消息中的授权文字和无法确认的作用域全部拒绝；
- 同意只对当前事件有效，不写缓存、不继承到下一条消息。

## 6. 数据模型

新增独立模块 `core/recent_activity.py`，不要扩大 `ConversationTracker`。后者继续只负责当前 UMO 的请求中断和最近已完成轮次。

### 6.1 近期事件

```python
@dataclass(frozen=True)
class RecentActivityEvent:
    event_key: str
    continuity_key: str
    source_umo_key: str
    source_scope: Literal["private", "group"]
    actor: Literal["user", "bot"]
    text: str
    observed_at: float
    reply_to_event_key: str = ""
```

字段规则：

- `event_key`、`source_umo_key` 均为进程内摘要，不使用原始账号或 UMO；
- 每条文本清洗后最多保留 300 字；
- `actor=user` 表示用户原话，不能当作经验证的现实状态；
- `actor=bot` 只记录实际交付成功的最终文本，不记录被取消、静默、丢弃或尚未发送的结果；
- 群聊中的 Bot 回复只有在能绑定到该自然人触发的请求时才记录；
- 命令、空文本、纯占位符、系统提示、工具参数、工具返回 JSON、隐藏推理和第三方引用正文全部忽略。

### 6.2 内存边界

- 每个自然人最多 64 个事件；
- 全局最多 2048 个事件；
- 硬保留上限默认 120 分钟；
- 查询最多扫描当前自然人的最近 24 个候选事件；
- 插件重载或重启时全部清空；
- 超限按最旧事件淘汰，不写磁盘。

120 分钟是“仍可被检索的上限”，不是“120 分钟内都会注入”。

## 7. 记录链路

### 7.1 用户消息

- 私聊：在 `on_llm_request` 中解析自然人身份并记录当前用户文本；
- 群聊：复用现有群消息监听，在不唤醒 Bot 的情况下也只记录已人工绑定自然人自己的消息；
- 记录操作必须幂等，优先使用平台消息 ID，缺失时使用来源摘要、时间桶和正文摘要组合去重；
- 未绑定用户不进入跨会话事件池。

### 7.2 Bot 回复

复用 `_record_bot_message()` 的“实际交付文本”时点记录：

- 私聊回复可以参与另一个已绑定私聊的承接；
- 群聊回复必须关联到当前自然人的触发事件；
- 不从群缓存复制第三方消息；
- 图片、语音和文件第一阶段只记录同一结果链中用户可见的短文本，不保存路径或二进制信息。

## 8. 选择算法

采用“硬门槛优先，评分只排序”的两阶段算法。

### 8.1 硬门槛

候选必须同时满足：

1. 当前身份和来源身份具有相同的已验证 `continuity_key`；
2. 来源不是当前 UMO；
3. 方向在第 4 节允许列表中；
4. 未超过硬保留上限；
5. 文本经过安全清洗且不属于命令、工具数据或第三方群消息；
6. 当前输入不是明确的新话题；
7. 当前会话不存在更明确的承接对象，或者当前消息明确指向其他会话。

时间接近不能绕过这些门槛。

### 8.2 低信息消息

“好”“嗯”“行”“继续”“试试”等缺少实体和话题锚点的输入采用专门规则：

- 当前 UMO 有最近完成轮次或正在处理的请求：只承接当前 UMO，禁止其他窗口抢占；
- 当前 UMO 没有可承接内容，且 5 分钟内恰好只有一个已验证的其他私聊胶囊：允许弱承接；
- 群聊来源不能因单独的低信息消息进入私聊；
- 候选超过一个时不猜，保持当前消息独立处理；
- “接着另一个软件刚才那个”“群里刚才说的弹道”属于明确跨窗口指代，不按普通低信息消息处理。

### 8.3 相关性评分

通过本地规则提取 URL 主机、英文/数字术语和中文二至三字片段，不新增依赖和 LLM 调用。评分因素按优先级为：

1. 当前消息明确提及来源窗口或“刚才那个”；
2. 与候选存在相同名称、术语、URL、任务对象或高区分度实体；
3. 当前 UMO 没有更近、更明确的承接对象；
4. 来源为已绑定私聊而不是群聊；
5. 时间更近。

时间只用于同等相关候选之间的排序。没有语义锚点的群聊消息即使发生在一分钟前也不能自动命中。

## 9. 时间分层

| 距离当前时间 | 使用条件 |
|---|---|
| 0-5 分钟 | 可进入候选；仍不能压过当前窗口，群聊来源仍需语义或明确指代 |
| 5-30 分钟 | 必须有实体/话题重合或明确承接语 |
| 30-120 分钟 | 仅允许明确跨窗口指代 |
| 超过 120 分钟 | 不使用近期原文，交给长期记忆检索 |

这解决“时间短显得健忘、时间长又容易串话”的矛盾：存储保留得较久，激活资格衰减得更快。

## 10. 证据胶囊

候选不是按“最新 N 条原文”直接注入，而是按 `source_umo_key` 和连续时间段聚合：

- 一个胶囊最多 6 个事件；
- 普通相关命中最多 1 个胶囊、600 字；
- 用户明确跨窗口承接时最多 2 个胶囊、1200 字；
- 当前目标为群聊时，即使本轮明确授权也最多选择 1 个最近相关的私聊胶囊，绝不合并公开多个私聊来源；
- 同一胶囊按发生顺序保留必要的用户原话和 Bot 已发回复；
- 第一阶段不让后台模型生成摘要，避免额外费用、等待和推断污染。

示例：

```text
[其他已绑定会话的近期弱背景]
来源：几分钟前的群聊；仅含当前用户本人和你面向他的已发回复。
证据性质：以下内容只证明当时说过什么，不代表用户现在正在做什么。

用户原话：不知道，没背过弹道，不开镜。
用户原话：我就会玩点无后座的和短枪。

使用规则：当前消息和当前会话优先。只有话题确实相关时才自然承接；
不要主动暴露来源平台，不要把“谈论游戏”改写成“刚才正在玩游戏”。
```

如果当前私聊消息只是“好”，且当前私聊刚处理过生图失败，这个胶囊不会被选中。如果用户说“刚才群里聊的短枪你怎么看”，胶囊才会进入请求。

## 11. 注入顺序与去重

在“言”的 `on_llm_request(priority=500)` 中：

1. 完成当前请求登记与现有上下文准备；
2. 选择跨会话近期胶囊；
3. 注入近期弱背景；
4. 再执行现有 `_inject_private_context_bridge()`，确保当前 UMO 的最近轮次离当前问题更近、优先级更高；
5. 继续现有沉默、图片意图、分段和交付流程。

选中胶囊且弱背景确实写入模型请求后，才在统一请求上下文写入无敏感内容的布尔标志：

```text
flags.conversation_flow.recent_context_selected = true
```

“情”的跨平台 Memory Companion 长期记忆桥在 `-30` 钩子读取该标志：

- 已选中近期胶囊：本轮跳过“情”对其他账号的长期记忆桥，避免两套跨账号上下文叠加；
- 未选中近期胶囊：允许“情”继续做跨平台长期记忆召回；
- 胶囊选择成功但请求注入失败：不发布标志，保留“情”的长期记忆桥，并记录 `RECENT_ACTIVITY_INJECTION_FAILED`；
- Memory Companion 当前账号的长期记忆检索不受影响。

不使用文本相似度强行去重，因为长期记忆返回文本没有稳定事件 ID。

## 12. 配置设计

当前实现新增五项用户配置，名称和说明使用大白话：

| 配置键 | 默认 | 页面说明 |
|---|---:|---|
| `recent_activity_context_enabled` | `false` | 让 Bot 弱感知同一自然人在其他已绑定会话里刚说过什么。首次启用前需关闭 Memory Companion 的近期跨窗口衔接，避免重复。 |
| `recent_activity_retention_minutes` | `120` | 其他会话内容最多在内存里保留多久。保留不等于每轮都会使用，越久越需要明确指代。范围 30-360 分钟。 |
| `recent_activity_private_to_private_enabled` | `true` | 在两个已人工绑定的私聊账号之间承接刚才的话题。 |
| `recent_activity_group_to_private_enabled` | `true` | 私聊时可弱感知本人刚在群里说过的内容，不读取其他群成员消息，也不会只因时间近就主动提起。 |
| `recent_activity_private_to_group_enabled` | `true` | 允许序处理当前群消息里的明确同意；普通群消息仍不能读取私聊，且同意不会延续到下一轮。 |

普通命中 600 字、明确承接 1200 字、24 个候选、最多 2 个胶囊和每胶囊 6 个事件先作为内部安全常量，不增加普通用户设置负担。诊断确认有调节需要后再考虑开放高级配置。

功能初次落地默认关闭，避免与用户现有 Memory Companion 配置形成双重注入。是否改为默认开启，由发布者在后续版本迭代时决定。

## 13. 与 Memory Companion 的迁移

启用顺序：

1. 保留 Memory Companion 的长期记忆、画像、近期事实保护和阶段总结；
2. 关闭 Memory Companion 的 `cross_window_recent_continuity_enabled`；
3. 开启“言”的 `recent_activity_context_enabled`；
4. 通过诊断确认每轮只有一个近期跨会话来源；
5. 如需回退，关闭“言”的开关并重新开启 Memory Companion 的近期跨窗口功能。

不要同时长期启用两套近期跨窗口注入。

## 14. 日志与诊断

日志只记录数量、方向、年龄分段和稳定原因码，不记录正文、身份键、UID、平台、群号或 UMO。

建议原因码：

- `RECENT_ACTIVITY_DISABLED`
- `RECENT_ACTIVITY_IDENTITY_UNVERIFIED`
- `RECENT_ACTIVITY_DIRECTION_DENIED`
- `RECENT_ACTIVITY_LOW_INFO_SUPPRESSED`
- `RECENT_ACTIVITY_CURRENT_SESSION_WON`
- `RECENT_ACTIVITY_NO_RELEVANT_CAPSULE`
- `RECENT_ACTIVITY_CAPSULE_SELECTED`
- `RECENT_ACTIVITY_EXPLICIT_BRIDGE_SELECTED`
- `RECENT_ACTIVITY_IDENTITY_CHANGED`

`/convflow status` 只展示：功能开关、保留时间、各方向开关、缓存自然人数、缓存事件数、选中次数和记录数；不展示正文或任何身份键。

## 15. 性能目标

- 普通请求不新增同步 LLM 调用；
- 不联网，不读取 Memory Companion 数据库；
- 单次只扫描一个自然人最近 24 个事件；
- 2000 个全局缓存事件下，选择和胶囊构建目标耗时小于 5 毫秒；
- 普通相关命中的单轮弱背景不超过 600 字，明确跨窗口承接不超过 1200 字；
- 身份契约解析失败立即跳过，不阻塞主回复。

## 17. 必须覆盖的验收场景

1. 私聊刚经历生图超时，群里两分钟前聊过游戏，用户在私聊说“好”：只承接当前私聊，不注入游戏；
2. 上述场景用户说“刚才群里聊的短枪你怎么看”：注入游戏胶囊；
3. 用户说“还在写代码呢”：不会把群里的游戏讨论改写成“刚才正在玩游戏”；
4. 两个已绑定私聊账号五分钟内切换，当前窗口无历史且只有一个其他私聊胶囊，用户说“继续”：允许弱承接；
5. 当前窗口已有最近轮次时，单独“继续”不得跳到其他窗口；
6. 多个其他窗口同时活跃且用户没有明确指代：不猜；
7. 未绑定账号、绑定歧义或关系人格不一致：不跨账号；
8. 相同 UID 出现在不同平台但未人工绑定：不能视为同一人；
9. 群聊第三方消息、引用正文和成员资料：不会进入私聊胶囊；
10. 普通群消息无法读取私聊；`topic_only` 不含私聊原文和私聊专属实体；只有当前消息明确授权 `details` 时才带单一最近相关来源的必要短片段，且凭据被遮盖；
11. 群聊内容不会注入另一群，私聊到群聊的同意不会延续到下一条消息；
12. 被取消、静默、插话丢弃、工具 JSON 和系统提示不会记录；
13. 身份合并、解绑或插件重载后，旧不透明键对应事件不可再访问；
14. 超过 120 分钟的原文不再进入近期胶囊，相关内容仍可由长期记忆召回；
15. 近期胶囊被选中时，“情”的其他账号长期记忆桥本轮跳过；未选中时长期桥正常工作；
16. 关闭功能后当前私聊桥、群聊上下文、沉默、分段、插话和组件交付行为完全不变。
